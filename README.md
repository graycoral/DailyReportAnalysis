# AV 리포트 · Daily Report Analysis

Windows PC에서 자율주행 데일리 리포트를 검색하고, 사건의 시간 흐름과 기업 관계를 확인하는 로컬 프로그램입니다.

**회사 PC에서 AI를 실행하거나 AI API를 호출하지 않습니다.** 조사·분류·관계 분석을 마친 데이터를 GitHub에서 받아 표시합니다.

프로젝트의 배경·목적·기능·동작 원리·DB·운영 절차는 **[프로젝트 상세 설명서](docs/PROJECT_GUIDE.md)**에서 확인할 수 있습니다.

## 처음 사용하기

1. **[AVReportHub-Setup.exe 실행 파일 하나 받기](https://github.com/graycoral/DailyReportAnalysis/releases/latest/download/AVReportHub-Setup.exe)**
2. 받은 파일을 더블클릭하면 **검사 → 설치 → DB 준비 → 바로가기 생성 → 리포트 실행**이 자동으로 진행됩니다.
3. 다음부터 바탕화면의 **AV Report Hub**를 실행합니다.

ZIP 압축 해제, 프로그램별 추가 다운로드, 개발 도구 설치, 저장소 주소 입력이 필요 없습니다. 첫 실행 파일을 받는 단계 외에는 Setup이 자동 처리합니다. 문제가 발생한 경우에만 복구 설정 화면을 보여줍니다.
**Git·Python·Node.js·Go·별도 .NET 런타임을 설치할 필요가 없습니다.** 실행 환경과 화면 파일이 EXE에 포함되어 있으며 관리자 권한을 요구하지 않습니다.

Windows 10/11의 Intel·AMD **64비트(x64)** PC와 기본 웹 브라우저를 대상으로 합니다. ARM64 전용 배포본은 아직 제공하지 않습니다. 인터넷은 자료 갱신과 외부 원문 열람에 사용합니다.

> v0.1.1은 코드 서명 인증서가 없는 배포본입니다. 조직의 실행 제한이나 보안 경고를 프로그램이 해제하지 않습니다. 실행이 차단되면 회사에서 허용하는 배포 절차를 이용하세요.

## 두 실행 파일의 역할

| 파일 | 기능 |
| --- | --- |
| `AVReportHub-Setup.exe` | 내장 실행 환경·Windows 버전·저장 폴더 쓰기·GitHub 접근·게시 데이터 검증, 실행 파일 설치, 바로가기 생성 |
| `AVReportHub.exe` | 설정 확인 후 화면 시작, 최신 자료 동기화, 검색·타임라인·그래프 표시 |

Setup 안에 실행 프로그램이 포함됩니다. 설치 후 위치는 `%LOCALAPPDATA%\AVReportHub\bin\AVReportHub.exe`입니다. 바로가기 생성이 제한되면 이 파일을 직접 실행할 수 있습니다.

처음부터 실행 파일만 열어도 설정이 없거나 손상됐으면 환경 설정 화면을 엽니다. 프로그램은 누락된 자료 폴더를 자동 생성합니다. GitHub 접근 권한, 회사 방화벽·프록시 정책, OS 업그레이드처럼 사용자의 승인이 필요한 환경은 자동으로 변경하지 않고 해당 실패 원인을 안내합니다.

## 화면 사용

- **검색:** 리포트 제목·요약·본문·기업·분류를 검색합니다. 여러 단어를 입력하면 모두 포함하는 리포트를 찾습니다.
- **타임라인:** 사건 날짜와 보관 기록을 표시합니다. 예정일은 `계획`, 과거 발송 기록은 `보고일`로 표시하여 실제 사건 발생일과 구분합니다.
- **관계 그래프:** 사전에 근거가 연결된 관계만 표시합니다. 그래프 아래 관계 목록 또는 노드를 선택하면 근거 문장과 출처가 오른쪽에 열립니다.
- **오른쪽 상세 영역:** 요약, 원문 출처, MD·PPTX 다운로드, 연결된 이슈, 상세 본문을 볼 수 있습니다.
- 기업·기간·분류 필터와 선택 리포트는 탭 전환 중 유지됩니다.
- `같은 기업이 등장한 리포트`는 단순 태그 일치입니다. 확인된 후속 사건과 별도로 표시합니다.

## 최신화와 종료

- 실행 시 현재 저장된 자료를 먼저 보여주고 GitHub 최신 자료를 확인합니다.
- 기본 갱신 시간은 매일 **08:00, 한국시간**입니다. 설정에서 바꿀 수 있습니다.
- 설정 시각이 지났는데 실패하면 실행 중 15분 간격으로 재시도합니다.
- PC 종료·절전 중에는 갱신하지 못합니다. 다시 실행하거나 실행 중 절전에서 돌아오면 누락 여부를 확인합니다.
- **브라우저 창을 닫아도 로컬 프로그램은 실행 중**입니다. 화면의 `종료`로 프로그램을 끝낼 수 있습니다. 다시 실행 파일을 누르면 이미 실행 중인 화면을 엽니다.
- v0.1.1은 Windows 로그인 자동 시작, 작업 스케줄러 등록, 트레이 아이콘을 추가하지 않습니다.
- 인터넷이 끊겨도 받은 본문을 검색할 수 있습니다. 첨부는 최초 클릭 시 다운로드·검증·캐시하며, 기본 포함 첨부는 오프라인에서도 열립니다.

정시 갱신은 **GitHub에 게시된 자료를 받는 기능**입니다. 이 실행 파일이 뉴스를 조사하거나 매일 리포트를 생성하지 않습니다. 사용자 공개 승인에 따라 **2026-09-20~2026-10-14 발송 리포트 19건, MD·PPTX 38개**와 SQLite DB를 포함합니다. 일일 게시 작업 연결은 별도 단계입니다.

## 과거 리포트 DB

- SQLite DB에 발송본 본문·출처·첨부 메타데이터·사건·관계를 저장하며 검색 검증용 FTS5 인덱스를 포함합니다. `data/reports.sqlite`로 공개 게시합니다.
- `data/catalog.json`: 같은 DB에서 내보낸 화면용 데이터입니다. 회사 PC에서는 이 파일을 검색하므로 SQLite 설치나 AI 실행이 필요 없습니다.
- 설치 시 DB는 `%LOCALAPPDATA%\AVReportHub\databases\<SHA256>.sqlite`에 자동 저장됩니다. 새 DB도 GitHub 동기화 시 자동 수신·검증합니다.
- 발송 이력의 날짜·제목·첨부 파일명·바이트 크기를 대조했습니다. 로컬 작업본과 크기가 달랐던 PPTX 5개는 실제 Gmail 첨부를 회수했습니다. 메일 주소·메시지 ID·메일 본문은 저장소에 넣지 않았습니다.
- 과거 기사 사실을 새로 검증한 데이터가 아니라 **당시 발송본 보관**입니다. 전체 본문 검색은 19건 모두 지원하며, 그래프의 개별 사실 관계는 근거를 정리한 항목부터 표시합니다.
- 편입 결과는 [import-audit.json](data/import-audit.json), 원본은 [data/reports](data/reports)에 보관합니다. DB 생성 스크립트는 게시 환경에서만 실행합니다.

## 자료 저장 및 인증

`%LOCALAPPDATA%\AVReportHub` 아래에 설정, 마지막 정상 데이터, 첨부 캐시, 로그를 저장합니다. 프로그램 교체 시 자료가 유지됩니다. `bin` 폴더의 EXE만 교체하거나 Setup을 다시 실행해 업데이트할 수 있습니다. Setup 재실행 전 실행 중인 프로그램을 종료하세요.

현재 저장소는 공개이므로 인증 없이 읽습니다. 비공개 저장소를 사용할 경우 해당 저장소의 **Contents: Read-only** 권한을 가진 GitHub fine-grained token을 입력할 수 있습니다. 토큰은 Windows 현재 사용자 계정의 DPAPI로 암호화하여 `token.bin`에 저장하며 화면·로그·저장소에 출력하지 않습니다. 다른 PC나 계정에서는 토큰을 다시 설정하세요.

로컬 서버는 `127.0.0.1`의 사용 가능한 임시 포트에만 열립니다. 외부에서 접속할 수 없으며, 세션 쿠키·Host/Origin 검사로 보호합니다. 제3자 CDN·웹 폰트·분석 추적기를 사용하지 않습니다.

## 오류가 발생하면

| 화면 안내 | 조치 |
| --- | --- |
| GitHub 연결 불가 | 회사 PC에서 `api.github.com` HTTPS 접근과 프록시·인증서 확인. TLS 검증은 끄지 않습니다. |
| 저장소·브랜치·데이터 없음 | 소유자·저장소·브랜치와 `data/catalog.json` 게시 여부 확인 |
| 인증 실패 / 접근 권한 | 비공개 저장소 토큰 만료·읽기 권한 확인 |
| 실행 파일 설치 불가 | 실행 중인 AV 리포트를 종료하고 Setup 재실행 |
| 바로가기 생성 제한 | 설치 경로의 `AVReportHub.exe` 직접 실행 |
| 네트워크 준비 전 먼저 사용 | Setup의 `지금은 오프라인으로 시작` 선택 |

현재 네트워크는 Go의 환경변수 기반 HTTP(S) 프록시 설정을 사용합니다. 회사의 PAC 자동 검색이나 인증 프록시는 이 버전에서 별도로 구현하지 않았습니다. 필요한 경우 회사 환경에 맞춘 추가 설정을 검토합니다.

## 게시자: 데이터 갱신 규칙

전체 형식은 [데이터 계약](docs/DATA_CONTRACT.md)을 참고하세요.

1. 외부 분석 환경에서 사실·출처를 확인하고 사건과 관계를 정리합니다.
2. 날짜별 MD·PPTX를 `data/reports/YYYY-MM-DD/`에 둡니다.
3. 누적 목록·본문·사건·관계를 `data/catalog.json`에 반영합니다.
4. **관련 파일을 한 커밋으로 게시**합니다. 로컬 앱은 커밋을 고정하여 본문·첨부가 섞이지 않도록 읽습니다.
5. 기존 리포트 ID를 유지하며 수정합니다. 계획이 실현되면 과거 계획을 남기고 새 사건을 연결합니다.

AI 분석용 API 키, 메일 인증 정보, 개인 메일 원문은 프로그램 배포에 필요하지 않습니다. 이 공개 저장소에는 공개 가능한 자료만 게시하세요.

## 개발 및 검증

사용자는 아래 도구가 필요하지 않습니다. 개발자 빌드는 **Go 1.27.2** 기준, 외부 Go 모듈 의존성이 없습니다.

```powershell
./scripts/build.ps1
```

GitHub Actions는 Windows에서 단위 테스트(DPAPI·파일 교체 포함), 두 EXE 빌드, 설치·실행 HTTP 검사 후 ZIP을 배포합니다. [Actions](https://github.com/graycoral/DailyReportAnalysis/actions)에서 결과를 확인할 수 있습니다.

개발 중 로컬 실행:

```sh
go test ./internal/...
go run ./cmd/viewer --no-browser --data-dir ./build/test-data
```

콘솔에 표시되는 접속 주소는 해당 로컬 세션 전용입니다. 타인에게 공유하지 마세요. Windows 배포본은 콘솔 창을 표시하지 않습니다.
