# AV 리포트 · Daily Report Analysis

Windows PC에서 자율주행 데일리 리포트를 검색하고, 사건의 시간 흐름과 기업 관계를 확인하는 로컬 프로그램입니다.

**회사 PC에서 AI를 실행하거나 AI API를 호출하지 않습니다.** 조사·분류·관계 분석을 마친 데이터를 GitHub에서 받아 표시합니다.

**처음 사용하는 분은 [시작 안내](docs/USER_GUIDE.md)만 보시면 됩니다.** 설치 1분, 화면 설명, 자주 하는 질문을 그림과 함께 담았습니다.

프로젝트의 배경·목적·기능·동작 원리·DB·운영 절차는 **[프로젝트 상세 설명서](docs/PROJECT_GUIDE.md)**에서 확인할 수 있습니다.

## 처음 사용하기

1. **[AVReportHub-Setup.exe 실행 파일 하나 받기](https://github.com/graycoral/DailyReportAnalysis/releases/latest/download/AVReportHub-Setup.exe)**
2. 받은 파일을 더블클릭하면 **검사 → 설치 → DB 준비 → 바로가기 생성 → 리포트 실행**이 자동으로 진행됩니다.
3. 다음부터 바탕화면의 **AV Report Hub**를 실행합니다.

설치 파일과 바탕화면 바로가기는 파랑·청록 바탕의 **AV 아이콘**을 사용합니다. 아이콘도 EXE에 포함되어 별도 파일을 받을 필요가 없습니다.

ZIP 압축 해제, 프로그램별 추가 다운로드, 개발 도구 설치, 저장소 주소 입력이 필요 없습니다. 첫 실행 파일을 받는 단계 외에는 Setup이 자동 처리합니다. 문제가 발생한 경우에만 복구 설정 화면을 보여줍니다.
**Git·Python·Node.js·Go·별도 .NET 런타임을 설치할 필요가 없습니다.** 실행 환경과 화면 파일이 EXE에 포함되어 있으며 관리자 권한을 요구하지 않습니다.

Windows 10/11의 Intel·AMD **64비트(x64)** PC와 기본 웹 브라우저를 대상으로 합니다. ARM64 전용 배포본은 아직 제공하지 않습니다. 인터넷은 자료 갱신과 외부 원문 열람에 사용합니다.

> v0.1.6은 코드 서명 인증서가 없는 배포본입니다. 조직의 실행 제한이나 보안 경고를 프로그램이 해제하지 않습니다. 실행이 차단되면 회사에서 허용하는 배포 절차를 이용하세요.

## 두 실행 파일의 역할

| 파일 | 기능 |
| --- | --- |
| `AVReportHub-Setup.exe` | 내장 실행 환경·Windows 버전·저장 폴더 쓰기·GitHub 접근·게시 데이터 검증, 실행 파일 설치, 바로가기 생성 |
| `AVReportHub.exe` | 설정 확인 후 화면 시작, 최신 자료 동기화, 검색·타임라인·그래프 표시 |

Setup 안에 실행 프로그램이 포함됩니다. 설치 후 위치는 `%LOCALAPPDATA%\AVReportHub\bin\AVReportHub.exe`입니다. 바로가기 생성이 제한되면 이 파일을 직접 실행할 수 있습니다.

처음부터 실행 파일만 열어도 설정이 없거나 손상됐으면 환경 설정 화면을 엽니다. 프로그램은 누락된 자료 폴더를 자동 생성합니다. GitHub 접근 권한, 회사 방화벽·프록시 정책, OS 업그레이드처럼 사용자의 승인이 필요한 환경은 자동으로 변경하지 않고 해당 실패 원인을 안내합니다.

## 화면 사용

- **검색:** 리포트 제목·요약·본문·기업·분류를 검색합니다. 여러 단어를 입력하면 모두 포함하는 리포트를 찾고, 일치한 단어는 목록과 본문에서 노란색으로 강조됩니다.
- **타임라인:** 사건 날짜와 보관 기록을 월별로 표시합니다. 예정일은 `계획`, 과거 발송 기록은 `보고일`로 표시하여 실제 사건 발생일과 구분합니다.
- **관계 그래프:** 사전에 근거가 연결된 관계만 표시합니다. 노드나 연결을 가리키면 관련 항목만 강조되고, 선택하면 근거 문장과 출처가 오른쪽에 열립니다.
- **전체 지도:** 리포트·기업·분류를 하나의 지도로 연결한 화면입니다. 끌어서 옮기고 휠로 확대할 수 있으며, 기업·분류 노드를 누르면 필터가 적용되고 리포트 노드를 누르면 본문이 열립니다.
- **오른쪽 상세 영역:** 상세 본문이 가장 위에 펼쳐지고, 그 아래에 연결된 이슈·같은 기업 리포트(제목만)·원문 출처·MD·PPTX 다운로드가 있습니다.
- **리포트 숨기기·전체 복원:** 상세 위의 `내 화면에서 숨기기`를 누르면 검색·타임라인·그래프·지도와 연관 목록에서 제외합니다. 왼쪽의 `숨긴 리포트 전체 복원`으로 모두 다시 표시할 수 있습니다. 원본이나 다른 사용자의 화면은 바뀌지 않으며, 숨김 설정은 이 PC의 현재 사용자 자료 폴더에 저장되어 재실행·자료 갱신 후에도 유지됩니다. 검색 조건 `초기화`는 숨김을 해제하지 않습니다.
- 카드와 왼쪽 태그 목록의 기업·분류 칩을 누르면 그 조건으로 바로 필터됩니다. 다시 누르면 해제됩니다.
- **‘신규 확인 사항 없음’만 있는 언급 제외**(기본 켜짐): 리포트는 매일 지정 기업을 점검하고 "Avride·Bolt·…는 신규 확인 사항 없음"처럼 적기 때문에, 그대로 두면 `Avride` 검색이 거의 모든 리포트에 걸립니다. 이 옵션이 켜져 있으면 ‘없음’·‘확인되지 않았다’·‘제외’ 줄과 출처·참고 목록을 뺀 본문에서만 검색·기업 필터·지도 연결을 계산하고, 그런 줄에만 나온 기업 칩은 흐리게(취소선) 표시합니다. 왼쪽 검색 조건에서 끌 수 있습니다.
- 기업·기간·분류 필터와 선택 리포트는 탭 전환 중 유지됩니다. 탭은 주소의 `#timeline`·`#graph`·`#map`으로 기억됩니다.
- **테마:** 상단의 테마 선택에서 **Apple 라이트 / Apple 다크 / 클래식**(처음 디자인) 중 고를 수 있습니다. 처음에는 Windows의 다크 모드 설정을 따르며, 선택은 이 브라우저에만 저장됩니다.
- `같은 기업이 등장한 리포트`는 단순 태그 일치입니다. 확인된 후속 사건과 별도로 표시합니다.

## 최신화와 종료

- 실행 시 현재 저장된 자료를 먼저 보여주고 GitHub 최신 자료를 확인합니다.
- 기본 갱신 시간은 매일 **08:00, 한국시간**입니다. 설정에서 바꿀 수 있습니다.
- 설정 시각에 PC마다 0~10분의 무작위 지연을 더해 실행합니다(같은 회사망에서 GitHub 요청이 한꺼번에 몰리지 않도록). 실패하면 실행 중 15분 간격으로 재시도합니다.
- PC 종료·절전 중에는 갱신하지 못합니다. 다시 실행하거나 실행 중 절전에서 돌아오면 누락 여부를 확인합니다.
- **브라우저 창을 닫아도 로컬 프로그램은 실행 중**입니다. 화면의 `종료`로 프로그램을 끝낼 수 있습니다. 다시 실행 파일을 누르면 이미 실행 중인 화면을 엽니다.
- v0.1.6은 Windows 로그인 자동 시작, 작업 스케줄러 등록, 트레이 아이콘을 추가하지 않습니다.
- 인터넷이 끊겨도 받은 본문을 검색할 수 있습니다. 첨부는 최초 클릭 시 다운로드·검증·캐시하며, 기본 포함 첨부는 오프라인에서도 열립니다.

정시 갱신은 **GitHub에 게시된 자료를 받는 기능**입니다. 이 실행 파일이 뉴스를 조사하거나 매일 리포트를 생성하지 않습니다. 사용자 공개 승인에 따라 **2026-09-20~2026-10-14 발송 리포트 17건, MD·PPTX 34개**와 SQLite DB를 포함합니다. 이후 리포트는 [매일 자동 게시](#매일-자동-게시)로 추가됩니다.

## 과거 리포트 DB

- SQLite DB에 발송본 본문·출처·첨부 메타데이터·사건·관계를 저장하며 검색 검증용 FTS5 인덱스를 포함합니다. `data/reports.sqlite`로 공개 게시합니다.
- `data/catalog.json`: 같은 DB에서 내보낸 화면용 데이터입니다. 회사 PC에서는 이 파일을 검색하므로 SQLite 설치나 AI 실행이 필요 없습니다.
- 설치 시 DB는 `%LOCALAPPDATA%\AVReportHub\databases\<SHA256>.sqlite`에 자동 저장됩니다. 새 DB도 GitHub 동기화 시 자동 수신·검증합니다.
- 발송 이력의 날짜·제목·첨부 파일명·바이트 크기를 대조했습니다. 로컬 작업본과 크기가 달랐던 PPTX 5개는 실제 Gmail 첨부를 회수했습니다. 메일 주소·메시지 ID·메일 본문은 저장소에 넣지 않았습니다.
- 과거 기사 사실을 새로 검증한 데이터가 아니라 **당시 발송본 보관**입니다. 전체 본문 검색은 포함된 17건 모두 지원하며, 그래프의 개별 사실 관계는 근거를 정리한 항목부터 표시합니다.
- 편입 결과는 [import-audit.json](data/import-audit.json), 원본은 [data/reports](data/reports)에 보관합니다. DB 생성 스크립트는 게시 환경에서만 실행합니다.

## 멀티모달 검색 (실험, 선택)

분석 담당자가 자기 PC에서 `rag/rag_server.py`를 켜면 **🧪 멀티모달 검색** 탭이 활성화됩니다. PDF 페이지를 이미지로 임베딩(`google/embeddinggemma-2`, CPU, 오디오 인코더 미적재)해 문장으로 찾습니다. 배포본에는 모델이 들어 있지 않으며 서비스가 없는 PC에서는 안내만 표시됩니다. 올린 PDF는 암호화 없이 `%LOCALAPPDATA%\AVReportHub\rag\index`에 저장되므로(Git 저장소 안이면 서비스가 시작을 거부) 올리기 전에 경고 창이 뜹니다. 준비와 사용법은 [멀티모달 검색 안내](docs/RAG_GUIDE.md)를 보세요.

## 자료 저장 및 인증

`%LOCALAPPDATA%\AVReportHub` 아래에 설정, 마지막 정상 데이터, 첨부 캐시, 로그를 저장합니다. 프로그램 교체 시 자료가 유지됩니다. `bin` 폴더의 EXE만 교체하거나 Setup을 다시 실행해 업데이트할 수 있습니다. Setup은 실행 중인 프로그램에 종료를 요청한 뒤 교체합니다.

현재 저장소는 공개이므로 인증 없이 읽습니다. 비공개 저장소를 사용할 경우 해당 저장소의 **Contents: Read-only** 권한을 가진 GitHub fine-grained token을 입력할 수 있습니다. 토큰은 Windows 현재 사용자 계정의 DPAPI로 암호화하여 `token.bin`에 저장하며 화면·로그·저장소에 출력하지 않습니다. 다른 PC나 계정에서는 토큰을 다시 설정하세요.

로컬 서버는 `127.0.0.1`의 사용 가능한 임시 포트에만 열립니다. 외부에서 접속할 수 없으며, 세션 쿠키·Host/Origin 검사로 보호합니다. 제3자 CDN·웹 폰트·분석 추적기를 사용하지 않습니다.

## 내 자료 (사내 PDF · Outlook 메일, 이 PC 전용)

`🔒 내 자료` 탭에서 사내 자료를 리포트와 함께 볼 수 있습니다. **이 자료는 GitHub 동기화·게시와 완전히 분리되어 있으며 외부로 전송하지 않습니다.**

- **PDF**: 화면 어디에나 끌어다 놓거나 `내 자료` 탭에서 선택합니다(파일당 50MB). 사본은 `%LOCALAPPDATA%\AVReportHub\docs\pdf`에 현재 Windows 계정의 DPAPI로 암호화해 보관하므로 폴더를 다른 PC·계정으로 복사해도 열 수 없습니다. 리포트에 연결하거나 이 PC에서 삭제할 수 있습니다.
- **Outlook 메일**: 메일과 PST/OST 파일은 **복사하지 않습니다.** `Outlook 메일함 불러오기`로 현재 메일함을 고르거나 PST·OST 파일 경로를 지정하면, 리포트를 열 때 리포트의 기업명으로 전후 30일 메일을 찾아 제안합니다. 직접 검색도 할 수 있습니다. 연결하면 메일 ID와 제목·보낸 사람·날짜만 암호화해 저장하고, 누르면 Outlook에서 원본이 열립니다.
- 지정한 PST는 Outlook 폴더 목록에 추가됩니다. OST는 현재 Outlook 프로필에 연결된 메일함만 사용할 수 있습니다.
- 클래식 Outlook이 필요합니다(새 Outlook 미지원). 회사 정책으로 PowerShell 제한 모드가 켜져 있으면 Outlook 연결을 쓸 수 없습니다.
- 끌어다 놓은 `.pst`·`.ost`·`.msg` 파일은 받지 않습니다. 저장 폴더가 Git 저장소 안에 있으면 내 자료를 보관하지 않습니다.

## 오류가 발생하면

| 화면 안내 | 조치 |
| --- | --- |
| GitHub 연결 불가 | 회사 PC에서 `api.github.com` HTTPS 접근과 프록시·인증서 확인. TLS 검증은 끄지 않습니다. |
| 저장소·브랜치·데이터 없음 | 소유자·저장소·브랜치와 `data/catalog.json` 게시 여부 확인 |
| 인증 실패 / 접근 권한 | 비공개 저장소 토큰 만료·읽기 권한 확인 |
| 실행 파일 설치 불가 | Setup이 실행 중인 AV 리포트를 자동 종료합니다. 그래도 실패하면 화면의 `종료`를 누른 뒤 Setup 재실행 |
| 바로가기 생성 제한 | 설치 경로의 `AVReportHub.exe` 직접 실행 |
| 네트워크 준비 전 먼저 사용 | Setup의 `지금은 오프라인으로 시작` 선택 |

현재 네트워크는 Go의 환경변수 기반 HTTP(S) 프록시 설정을 사용합니다. 회사의 PAC 자동 검색이나 인증 프록시는 이 버전에서 별도로 구현하지 않았습니다. 필요한 경우 회사 환경에 맞춘 추가 설정을 검토합니다.

전체 형식은 [데이터 계약](docs/DATA_CONTRACT.md)을 참고하세요.

### 매일 자동 게시

ChatGPT가 매일 아침 리포트를 만들어 이 저장소의 `main` 브랜치에 push합니다. 그 뒤는 GitHub Actions가 처리하며, 사용자 PC나 게시자 PC에서 돌리는 작업은 없습니다.

1. ChatGPT가 `data/reports/YYYY-MM-DD/`에 MD·PPTX를 push합니다. 이 push가 `publish-data` 워크플로를 깨웁니다.
2. `scripts/import-history.py --from-reports`가 폴더를 스캔해 `catalog.json`·`reports.sqlite`·`import-audit.json`을 다시 만듭니다. 제목은 MD 머리말의 `info`, 기업 태그는 `data/companies.json` 목록으로 본문을 대조해 채우되, "신규 확인 사항 없음" 같은 점검 줄·출처 목록·URL에만 나오는 기업은 태그하지 않습니다(화면의 ‘없음’ 언급 제외와 같은 규칙).
3. 변경이 있을 때만 한 커밋으로 push합니다. 사용자 PC는 08:00 KST 갱신(또는 `지금 업데이트`)으로 이 커밋을 받습니다.

ChatGPT 쪽이 지켜야 할 파일 위치·머리말·본문 구성·표기 규칙은 **[리포트 작성·게시 규칙](docs/REPORT_FORMAT.md)**에 정리했습니다. 기존 발송본(2026-10-14)의 형식을 기준으로 삼았습니다. 08:00 전에 push가 끝나야 그날 아침 갱신에 포함됩니다.

### 손으로 보정할 때

1. 날짜별 MD·PPTX를 `data/reports/YYYY-MM-DD/`에 둡니다. 나머지는 Actions가 만듭니다.
2. 요약·기업·분류·출처·사건·관계는 `data/catalog.json`에서 직접 고칩니다. 스크립트는 **이미 있는 리포트 ID의 편집 내용을 보존**하고 본문·첨부만 새로 읽습니다.
3. 관계는 근거·출처·리포트 ID가 있어야 합니다. 형식은 [데이터 계약](docs/DATA_CONTRACT.md)을 따릅니다.
4. 기존 리포트 ID를 유지하며 수정합니다. 계획이 실현되면 과거 계획을 남기고 새 사건을 연결합니다.

AI 분석용 API 키는 프로그램 배포에 필요하지 않습니다. 메일 인증 정보는 GitHub Secrets에만 두고, 이 공개 저장소에는 공개 가능한 자료만 게시하세요.

## 개발 및 검증

사용자는 아래 도구가 필요하지 않습니다. 개발자 빌드는 **Go 1.27.2** 기준, 외부 Go 모듈 의존성이 없습니다.

```powershell
./scripts/build.ps1
```

GitHub Actions는 Windows에서 단위 테스트(DPAPI·파일 교체 포함), 두 EXE 빌드, 설치·실행 HTTP 검사 후 ZIP을 배포합니다. [Actions](https://github.com/graycoral/DailyReportAnalysis/actions)에서 결과를 확인할 수 있습니다.

Release 게시 중 `HTTP 500`이 발생해도 앞선 `build` 작업이 성공했다면 실행 파일은 해당 Actions 실행의 **Artifacts → AVReportHub-Windows-x64**에서 받을 수 있습니다. 빌드와 게시를 별도 작업으로 나누었으므로 **Re-run failed jobs**는 실패한 게시 작업만 다시 실행합니다.

게시 스크립트는 파일별로 순서대로 업로드하며, GitHub의 5xx·429 또는 일시적인 연결 오류에는 최대 5회 재시도합니다. 이미 올라간 파일의 SHA-256이 같으면 교체하지 않고, 마지막에는 모든 첨부의 크기·상태와 제공되는 SHA-256을 확인합니다. `--clobber` 교체는 기존 파일을 먼저 삭제하므로 실패한 파일만 재시도하며, 계속 실패하면 작업을 실패 상태로 남깁니다. 워크플로 수정 후에는 변경을 push하고 **Run workflow**로 새 실행을 시작해야 수정된 구성이 적용됩니다. 기존 실행의 재실행은 기존 커밋을 사용합니다.

개발 중 로컬 실행:

```sh
go test ./internal/...
go run ./cmd/viewer --no-browser --data-dir ./build/test-data
```

콘솔에 표시되는 접속 주소는 해당 로컬 세션 전용입니다. 타인에게 공유하지 마세요. Windows 배포본은 콘솔 창을 표시하지 않습니다.
