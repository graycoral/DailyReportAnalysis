# AV Report Hub 사용자 가이드

**v0.1.9 · 2026-10-19 갱신 · Windows 10/11 64비트(x64)**

자율주행 데일리 리포트, Outlook 메일, PDF와 노트를 한곳에서 찾아보는 프로그램입니다. **앱 상단·설정·도움말**에서 실행 중인 버전을 확인할 수 있습니다.

기본 기능은 Git·Python·Node.js 설치 없이 사용할 수 있습니다. AI 검색은 별도 환경을 준비하고 직접 서비스를 켜는 선택 기능입니다.

## 1. 설치와 첫 실행

1. 배포받은 `AVReportHub-Setup.exe`를 실행합니다. 공개 배포본은 [GitHub 다운로드 페이지](https://github.com/graycoral/DailyReportAnalysis/releases/latest)에서도 받을 수 있습니다.
2. 실행 환경 확인, 프로그램 설치, 바탕화면 바로가기 생성이 끝나면 브라우저에서 앱이 열립니다. 관리자 권한이나 개발 도구가 필요하지 않습니다.
3. **GitHub 자료를 연동할까요?**에서 연동 여부를 선택합니다. 회사에서 GitHub를 사용하지 않으면 **연동하지 않기**를 선택하고 Outlook이나 직접 가져온 자료를 사용하세요.
4. 다음부터는 바탕화면의 **AV Report Hub**를 실행합니다. 브라우저 창만 닫아도 앱은 계속 실행됩니다. 완전히 종료하려면 왼쪽 아래 **종료**를 누릅니다.

처음 설치했을 때 기본 리포트가 자동으로 채워지지는 않습니다. GitHub 연동에 성공하거나 Outlook·MD 자료를 가져오면 목록에 표시됩니다.

새 버전을 처음 실행할 때도 GitHub 연동 여부를 한 번 선택합니다. 닫기나 Esc로 보류하면 다음 실행에서 다시 묻습니다. 이것은 설치된 버전에 대한 설정이며, 인터넷에서 새 버전 출시를 자동 확인하는 기능은 아닙니다.

서명되지 않은 앱에 대한 Windows 경고가 나타나면 배포 담당자와 파일 출처를 확인하세요. 회사 정책으로 실행이 차단된 경우 사내 IT 담당자의 안내를 따릅니다.

### GitHub가 연결되어 있다면

1. 리포트 화면 상단의 상태 표시를 눌러 **최신 자료 확인 완료**인지 확인합니다. 확인 중이면 잠시 기다립니다.
2. 왼쪽 **데일리리포트**를 누르고 제목을 선택하면 본문이 열립니다.
3. 새 자료를 바로 받으려면 상단 **지금 업데이트**를 누릅니다. 목록이 비어 있으면 검색 조건을 **초기화**합니다.

연결을 새로 하거나 복구하려면 **설정 → 자료 연결 · 자동 업데이트 → GitHub 자료 연동**을 켜고 **검사하고 저장**을 누릅니다. 기본 배포 자료는 기존 소유자·저장소·브랜치를 유지하고, 별도 저장소는 담당자가 알려 준 값을 사용합니다. 공개 저장소의 접근 토큰은 비워 둡니다.

### GitHub가 연결되어 있지 않다면

**GitHub 없이도 리포트를 사용할 수 있습니다.** 클래식 Outlook을 열어 메일을 볼 수 있는지 확인한 뒤, 이 앱의 **Outlook → 메일함에서 리포트 가져오기 → Outlook 메일함 불러오기 → 폴더 선택 → 이 폴더 추가** 순서로 리포트 메일이 있는 폴더를 연결합니다. 가져온 제목은 Outlook과 데일리리포트에서 읽을 수 있습니다.

별도로 받은 **PST(.pst)**는 메일을 담아 둔 보관 파일입니다. 아래 [PST 파일 연결](#pst-파일-연결)을 따라 파일을 추가한 뒤 **가져올 폴더까지 선택**하세요. 새 Outlook은 이 앱의 연동을 지원하지 않습니다.

Outlook이 없다면 받은 MD 리포트는 상단 **가져오기**, PDF는 **내 자료 → PDF 추가**로 시작할 수 있습니다. 정해진 리포트 양식이 아닌 일반 Markdown 문서는 **노트 → MD 가져오기**를 사용합니다.

## 2. 자료는 어디서 가져오나요?

| 자료 | 가져오는 방법 | GitHub 미연동 시 |
| --- | --- | --- |
| GitHub 리포트 | 첫 실행에서 연동하거나 **설정 → GitHub 자료 연동 → 검사하고 저장** | 표시·다운로드하지 않음. 기존 캐시는 보관 |
| Outlook 리포트 | **Outlook → 메일함에서 리포트 가져오기**에서 폴더 선택 | 가져오기·열람·MD 다운로드 가능 |
| 직접 가져온 MD | 상단 **＋ 가져오기** 또는 파일 끌어놓기 | 가져오기·열람·다운로드 가능 |
| PDF | **내 자료 → PDF 추가** | 파일명 검색·미리보기·리포트 연결 가능 |
| 노트 | **노트 → 새 노트** 또는 **MD 가져오기** | 작성·검색·리포트 연결 가능 |

**GitHub를 연결하지 않아도 Outlook 리포트는 데일리리포트 목록에 표시됩니다.** 데일리리포트는 가져온 리포트를 모아 읽는 화면입니다.

같은 보고일과 같은 본문은 데일리 목록에 한 번만 표시합니다. 머리말 설정, 줄바꿈, 줄 끝 공백 차이는 무시합니다. GitHub 게시본이 있으면 그 항목을 우선 표시하며, Outlook 탭에서는 메일에서 가져온 원본을 따로 확인할 수 있습니다. 출처가 다르고 본문도 다르면 같은 날짜라도 별도 항목으로 표시됩니다.

수동 MD와 Outlook 리포트는 각각 보관합니다. 각 가져오기 경로에서는 같은 보고일의 변경된 내용을 갱신하고, 동일한 내용을 다시 가져오면 중복 저장하지 않습니다.

## 3. 화면 둘러보기

왼쪽 메뉴에서 다음 아홉 화면으로 이동합니다.

| 화면 | 할 수 있는 일 |
| --- | --- |
| 데일리리포트 | 리포트 검색, 본문 읽기, MD·게시 첨부 다운로드 |
| 타임라인 | 정리된 사건과 보고일을 날짜순으로 확인 |
| 관계 | 기업·사건의 근거와 자료 간 연결 확인 |
| 지도 | 리포트·PDF·메일·노트를 한 그림에서 탐색 |
| Outlook | 메일함 연결, 폴더 선택, 가져온 리포트와 원본 메일 확인 |
| 내 자료 | PDF 보관, 파일명 검색, 미리보기, 리포트 연결 |
| 노트 | Markdown 작성, 미리보기, 태그·폴더 정리, 노트·리포트 연결 |
| AI 검색 | 별도로 색인한 PDF·이미지를 문장으로 검색 |
| 설정 | 화면 스타일, 숨긴 리포트 복원, GitHub 연동·갱신 시간 설정 |

목록과 본문 사이 경계선을 끌어 너비를 조절합니다. 더블클릭하면 기본 비율로 돌아갑니다. 키보드로는 경계선에 Tab으로 이동한 뒤 좌우 방향키로 조절하고 Enter로 초기화합니다. 좁은 화면에서 리포트를 읽은 뒤에는 **목록으로**로 돌아갈 수 있습니다.

**데일리리포트 탭의 숫자는 아직 열지 않은 새 문서 수입니다.** 이 기능을 처음 사용할 때 이미 보관된 리포트는 기준 자료로 두고, 이후 추가된 문서부터 셉니다. 목록의 **새 문서** 항목을 선택해 열면 숫자가 줄어들고, 모두 확인하면 배지가 사라집니다. 검색·기간 조건과 관계없이 표시하며, 같은 본문의 중복 문서는 한 번만 셉니다. 읽음 기록은 이 PC의 앱 데이터 폴더에 저장되어 브라우저나 프로그램을 다시 열어도 유지됩니다.

상단 신호등과 **마지막 업데이트 확인 · 한국시간**은 GitHub 자료 확인 상태입니다. Outlook의 가져오기 진행 상태와는 별개입니다. 초록색은 확인 완료, 노란색은 확인 중, 빨간색은 연결 실패, 회색은 연동 꺼짐·설정 전·대기 상태입니다. 신호등을 누르면 자세한 설명이 나옵니다.

왼쪽 아래 **도움말**은 간단한 안내 팝업을 엽니다. **자세한 도움말**을 누르면 **처음 사용하기**가 새 탭에 열리고 GitHub 연결 여부에 따른 시작 방법과 PST 연결을 안내합니다. **현재 화면 사용법**은 보던 탭의 설명을 바로 엽니다. 팝업을 닫아도 검색 조건과 읽던 리포트는 유지됩니다.

## 4. 리포트 검색과 읽기

1. 검색창에 회사명·지역·기술·키워드를 입력합니다. 띄어 쓴 여러 단어가 모두 포함된 리포트를 찾습니다.
2. **검색 조건**에서 기업·분류·시작일·종료일을 고릅니다. 회사 이름 칩을 눌러도 필터를 적용할 수 있습니다.
3. 제목을 눌러 본문을 읽습니다. 검색어는 목록과 본문에서 강조됩니다.
4. 조건의 **×**로 하나씩 해제하거나 **초기화**로 검색 조건을 지웁니다. 데일리리포트·타임라인·관계·지도 사이에서는 조건이 유지됩니다.

**검색 조건 → 상세 옵션**의 ‘신규 확인 사항 없음’ 제외가 켜져 있으면, 기업명이 변화 없는 점검 항목에만 나오는 자료는 해당 기업 검색에서 제외됩니다.

리포트 상세에서 **MD 다운로드**를 사용할 수 있습니다. **PPTX 다운로드**는 해당 첨부가 제공된 GitHub 게시본에서 표시됩니다. Outlook에서 가져온 리포트는 **Outlook 원문 열기**로 메일을 열어 다른 첨부를 확인하세요.

모든 자료 탭에서 **Ctrl+클릭**으로 선택을 추가하거나 해제합니다. 일반 클릭은 한 항목만 선택하며, 탭을 바꾸거나 검색 조건에서 제외되면 선택을 해제합니다. **Delete** 또는 **선택 삭제**로 휴지통에 보내고, 화면 위 **휴지통**에서 여러 항목을 선택해 복원할 수 있습니다. 관계 항목을 선택하면 그 관계의 근거 리포트를 선택합니다. 기업·분류는 파일 삭제 대상이 아닙니다.

**Shift+Delete**는 선택한 항목을 확인 후 완전히 삭제합니다. 휴지통에서는 Delete도 완전 삭제 확인 창을 엽니다. 노트는 이전 저장본도 삭제되며, 다른 노트에서 공유할 수 있는 첨부 이미지는 유지됩니다. 삭제 범위는 이 앱의 보관 사본과 연결이며 GitHub 게시 원본·Outlook 원본 메일·처음 가져온 파일은 유지됩니다. Windows 운영체제의 휴지통과는 별도인 **앱 휴지통**입니다. 검색창·제목·노트 편집기에서는 Delete가 글자를 지웁니다.

리포트의 일반 삭제는 원본을 보관하고 목록·타임라인·관계·지도에서 숨깁니다. 기존 **설정 → 삭제한 리포트 복원**에서도 선택 복원 또는 전체 복원할 수 있습니다. 완전히 삭제한 리포트는 전체 복원이나 자동 동기화로 돌아오지 않습니다.

## 5. Outlook 리포트 가져오기

**클래식 Outlook**이 설치되어 있고 사용할 메일함이 설정되어 있어야 합니다. 새 Outlook과 PowerShell 제한 모드에서는 사용할 수 없습니다.

1. **Outlook → 메일함에서 리포트 가져오기**를 펼칩니다.
2. **Outlook 메일함 불러오기**를 누르고 원하는 메일함의 **폴더 선택**을 누릅니다.
3. 가져올 폴더 옆의 **이 폴더 추가**를 누릅니다. 선택한 폴더만 확인하며, 하위 폴더는 각각 선택합니다.
4. **지금 가져오기**를 누르면 바로 확인합니다. 앱을 시작할 때와 실행 중 5분마다 자동으로 확인하며, 남은 메일은 나누어 이어서 처리합니다.

### PST 파일 연결

1. 리포트 메일이 들어 있는 `.pst` 파일을 이 PC에 준비합니다. 파일이 없다면 담당자에게 받거나 위의 메일함 불러오기를 이용합니다. PST 연결에도 **클래식 Outlook**이 필요합니다.
2. 이 앱에서 **Outlook → 메일함에서 리포트 가져오기**를 펼칩니다.
3. **경로 추가**를 누르고 PST 파일을 선택한 뒤 **열기**를 누릅니다. 전체 경로(예: `C:\Reports\DailyReport.pst`)를 입력하고 **입력 경로 추가**를 눌러도 됩니다.
4. **연결된 메일함·폴더** 목록에 추가된 파일 옆의 **폴더 선택**을 누릅니다.
5. 리포트 메일이 들어 있는 폴더의 **이 폴더 추가**를 누릅니다. 하위 폴더는 각각 선택합니다.
6. 가져오기가 끝나면 **Outlook에서 가져온 리포트**에 제목이 나타나는지 확인하고, 제목을 눌러 읽습니다. 데일리리포트에서도 확인할 수 있습니다.

**파일 경로만 추가하면 자동 가져오기가 시작되지 않습니다. 폴더 선택까지 완료해야 합니다.** ‘연결 폴더 0개’라면 4~5번을 진행하세요. 연결 후에는 PST 파일을 같은 위치에 두고, 새 메일을 바로 확인하려면 Outlook의 **지금 가져오기**를 누릅니다. 상단 **지금 업데이트**는 GitHub 자료 확인용입니다.

OST는 **현재 Outlook 프로필에 연결된 메일함만** 지원합니다. 다른 PC에서 복사해 온 OST만으로는 연결할 수 없습니다. 현재 메일함을 불러오거나 담당자에게 PST를 요청하세요. PST가 열리지 않으면 파일 위치·접근 권한과 클래식 Outlook에서 열 수 있는지 확인합니다.

### 어떤 메일을 리포트로 읽나요?

- 리포트 형식의 Markdown 본문 또는 UTF-8 `.md` 첨부를 읽습니다. MD는 파일당 최대 2MB입니다.
- 전달 메일에 원본 메일(`.msg`)이 첨부되어 있으면 **그 안의 MD도 읽습니다**.
- 현재 리포트 형식과 이전 자율주행 데일리 형식을 지원합니다. 날짜가 `info`에 있는 예전 형식, 섹션 이름의 차이, 여러 슬라이드로 반복된 섹션도 인식합니다.
- 일반 메일이나 리포트 구조가 없는 MD는 데일리리포트로 저장하지 않습니다. 일반 Markdown 문서는 **노트 → MD 가져오기**를 이용하세요.
- 폴더명은 분류 태그로, 메일 제목에 명시된 알려진 기업명은 기업 태그로 사용합니다. 본문에서 기업 태그를 추론하지 않습니다.

v0.1.9의 `.msg` 지원을 적용하면 기존 선택 폴더를 **한 번 다시 검사**합니다. 메일이 많으면 몇 분 이상 걸릴 수 있습니다. 진행 위치를 저장하므로 완료 후에는 같은 과거 메일 전체를 반복해서 읽지 않습니다.

### 가져오기 결과 확인

| 안내 | 뜻과 확인할 사항 |
| --- | --- |
| 추가 / 변경 | 새로 저장하거나 내용이 갱신된 리포트 수 |
| 중복·제외 | 동일 내용, 일반 메일, 업데이트 없는 리포트 등 목록에 새로 추가하지 않은 항목 |
| MD 형식 확인 필요 | MD는 읽었지만 리포트 형식에 맞지 않은 항목. 메일 읽기 실패와 구분 |
| 일부 폴더·메일을 읽지 못함 | Outlook 연결·폴더 상태를 확인한 뒤 다시 가져오기. 읽지 못한 메일은 다음 확인 때 재시도 |
| 첨부 크기·개수 제한 | 가져오기 한도를 넘은 첨부. 원본 메일에서 파일 확인 |

Outlook 목록의 **데일리에 추가됨**은 데일리 목록에서도 볼 수 있다는 뜻입니다. **중복 · 데일리에 있음**은 같은 내용의 대표 항목이 이미 있다는 뜻이며, Outlook 원본은 그대로 열 수 있습니다.

**연결 해제**는 그 폴더의 자동 가져오기를 중단합니다. Outlook 원본과 이미 가져온 리포트는 남습니다. 가져온 리포트는 현재 Windows 계정으로 암호화해 이 PC에 보관하며 GitHub로 전송하지 않습니다.

## 6. 직접 가져온 MD, PDF와 노트

### MD 리포트

상단 **＋ 가져오기**를 누르거나 파일을 화면에 놓습니다. UTF-8, 최대 2MB이며 [리포트 작성 형식](REPORT_FORMAT.md)을 따릅니다. 파일별 추가·변경·중복·형식 오류를 표시합니다. 수동 가져오기는 현재 작성 형식을 검사합니다.

### PDF

**내 자료 → PDF 추가**로 보관합니다. 파일명으로 검색하고 제목을 눌러 미리봅니다. 페이지 이동·확대/축소와 **크게 보기**를 사용할 수 있습니다. 표시되지 않으면 **새 탭에서 열기**나 **다운로드**를 이용하세요.

파일명 옆 **연결 리포트**에서 관련 리포트를 고릅니다. 같은 제목이 있으면 게시 리포트·Outlook·직접 가져온 MD 표시를 보고 선택합니다. **해제**는 연결만 끊고 PDF는 보관합니다.

PDF의 **삭제**·**Delete**는 암호화된 사본과 연결을 휴지통에 보관합니다. 복원하면 같은 PDF와 연결을 다시 사용할 수 있습니다. **Shift+Delete** 또는 휴지통의 **완전 삭제**는 보관 사본을 실제로 삭제합니다.

### 노트

**노트 → 새 노트**에서 제목과 본문을 쓰면 자동 저장됩니다. **저장 완료**를 확인하고, **지금 저장** 또는 `Ctrl+S`로 즉시 저장할 수도 있습니다.

- 원문 편집·분할 미리보기·읽기·Live Preview를 선택합니다.
- 폴더와 태그로 정리하고 제목·본문으로 검색합니다.
- 이미지를 붙여넣거나 `[[노트 이름]]`으로 다른 노트에 연결합니다.
- 리포트 상세의 **관련 노트 작성** 또는 노트 아래 **연결된 리포트**로 출처를 연결합니다.
- **휴지통**에서 삭제한 노트를 복원하고 **이전 저장본**에서 최근 저장 이력을 확인합니다.
- **저장 폴더**를 바꾸면 그 위치의 노트를 엽니다. 기존 파일은 원래 위치에 남습니다.

노트는 평문 `.md` 파일입니다. 외부 편집 변경과 충돌 처리, 이미지·폴더 백업 방법은 [노트 사용 안내](NOTES_GUIDE.md)를 참고하세요.

## 7. 타임라인·관계·지도·자료 연결

타임라인의 **계획**은 예정된 일이며, **보고일**은 리포트 발송 날짜입니다. 가져온 리포트가 있다고 모든 사건·기업 관계가 자동으로 생성되는 것은 아닙니다.

관계 화면에서 선을 누르면 근거 문장과 출처가 나옵니다. 기업·사건의 확인된 관계와 개인 자료 사이의 참조 연결을 구분해서 읽으세요.

지도에서는 휠로 확대·축소하고 빈 곳을 끌어 이동합니다. 기업·분류·리포트를 선택하면 오른쪽에 관련 자료가 최신순으로 표시됩니다. 목록에서 자료를 열고 **관련 자료 목록**으로 돌아올 수 있으며, 지도 위치와 검색 조건은 유지됩니다. 노트를 선택하면 미리보기가 열리고 연결 없는 노트도 표시합니다. **Outlook / 데일리 리포트 / 내 자료 / 내 노트** 스위치는 관계·지도에 함께 적용됩니다. 모두 끄면 그림이 비어 보입니다.

전체 지도에서는 **보고일과 본문이 같은 리포트를 하나로 합치고** 목록에 **데일리 · Outlook** 출처를 함께 표시합니다. 원본 메일·PDF·노트 연결과 각 원본의 검색 정보는 유지합니다. 날짜나 본문이 다르면 별도로 표시하며, 관계 그래프는 출처별 게시 근거를 유지합니다.

검색어는 자료 이름·메일 제목과 노트 제목·본문·태그에도 적용됩니다. 기업·분류·기간 조건은 리포트에 적용됩니다. 연결선은 양쪽 자료가 모두 표시될 때만 나타납니다.

상단 **자료 연결**에서는 같은 메일 대화, 같은 문서 첨부, 문서·프로젝트 번호, 기업·프로젝트 사전과 제목을 바탕으로 관련 자료를 추천합니다. **연결 확정** 또는 **추천 제외**를 선택하고, 확정·제외 목록의 **판단 취소 · 다시 추천**으로 되돌릴 수 있습니다. 확정한 연결만 관계·지도에 표시됩니다. 이 기능은 AI 검색 서비스 없이 동작하며 기업 간 사실 관계를 자동 생성하지 않습니다.

## 8. AI 검색은 선택 기능입니다

**AI 검색 → 환경 설정**에서 필요한 환경을 준비한 뒤 **검색 서비스 시작**을 누릅니다. Python 3.10 64비트와 모델·패키지가 필요하며, 처음 준비할 때 인터넷과 여유 공간이 필요합니다. 기본 리포트·Outlook·PDF·노트 기능에는 이 준비가 필요하지 않습니다.

**PDF·이미지 추가**로 색인할 파일을 선택하거나 목록에 놓습니다. 파일당 최대 50MB입니다. 검색창에 문장을 입력하고 결과를 누르면 해당 페이지나 이미지가 오른쪽에 표시됩니다. **색인·모델 정보**에서 상세 상태를 확인할 수 있습니다.

색인한 자료는 서비스가 실행 중일 때 전체 지도에도 표시됩니다. 자료 사이의 유사도는 검색 모델의 비교 결과이며, 사실 확인 결과가 아닙니다. 서비스를 끄면 색인 자료가 지도에서 빠지고 노트·보관 PDF·리포트는 계속 사용할 수 있습니다.

검색 모델은 이 PC에서 실행합니다. AI 검색에 올린 사본·이미지·색인은 **암호화 없이 저장**됩니다. 업로드 안내를 확인하고 회사의 자료 취급 규칙에 맞게 사용하세요. 준비와 문제 해결은 [AI 검색 안내](RAG_GUIDE.md)를 참고하세요.

## 9. 설정·버전·업데이트

**설정 → 화면 스타일**에서 블루 라이트·블루 다크·블루 클래식을 선택합니다. 선택은 이 브라우저에 저장됩니다. 밝은 화면은 현대 블루와 라이트 샌드, 어두운 화면은 스카이 블루를 강조색으로 사용합니다. 리포트 본문은 읽기 편한 흰색 또는 어두운 남색 바탕으로 표시됩니다.

**설정 → 자료 연결 · 자동 업데이트**에서 GitHub 연동과 확인 시간을 설정한 뒤 **검사하고 저장**을 누릅니다. 기본 확인 시간은 오전 8시(한국시간)이며 앱이 실행 중이어야 합니다. **지금 업데이트**는 GitHub 자료를 확인하고, Outlook 메일은 Outlook 탭의 **지금 가져오기**로 확인합니다.

GitHub 연결·접근에 실패하면 연동이 자동으로 꺼집니다. 기존 캐시는 보관하지만 GitHub 리포트는 표시·다운로드하지 않습니다. 연결을 복구한 뒤 다시 켜고 저장하면 확인합니다. Outlook·직접 가져온 MD·PDF·노트에는 영향을 주지 않습니다.

프로그램을 업데이트하려면 새 `AVReportHub-Setup.exe`를 실행합니다. 저장된 자료와 설정은 유지됩니다. 완료 후 앱 상단·설정·도움말의 **버전 번호**를 확인하세요. **지금 업데이트** 버튼은 프로그램 EXE를 교체하지 않습니다.

## 10. 자료가 보이지 않거나 실행되지 않을 때

| 증상 | 확인할 것 |
| --- | --- |
| 처음 실행했는데 목록이 비어 있음 | GitHub 연동 또는 Outlook·MD 가져오기를 선택. 기본 리포트는 자동으로 넣지 않음 |
| GitHub는 껐는데 데일리에 리포트가 있음 | Outlook·직접 가져온 MD일 수 있음. 카드와 상세의 출처 확인 |
| Outlook을 연결했는데 리포트가 없음 | 메일함 연결 후 **폴더 선택 → 이 폴더 추가**까지 했는지 확인. **지금 가져오기**와 완료 상태 확인 |
| `.msg` 안의 MD가 보이지 않음 | v0.1.9 이상인지 확인. 재검사 완료를 기다린 뒤 형식 오류·읽기 실패 안내 확인 |
| 리포트 수가 메일 수보다 적음 | 일반 메일·중복·업데이트 없는 리포트·형식 오류는 새 리포트로 추가되지 않음 |
| 가져왔다고 나오지만 목록에 없음 | 검색어·기간·기업 조건 초기화, **설정 → 삭제한 리포트 복원** 확인 |
| 관계·지도가 비어 있음 | 표시할 자료 스위치와 검색 조건 확인. 해당 자료의 연결이 아직 없을 수도 있음 |
| 인터넷이 끊김 | Outlook·직접 가져온 자료는 계속 사용 가능. GitHub는 연결 실패로 연동이 꺼지면 복구 후 다시 켜야 함 |
| 브라우저를 닫아도 앱이 실행 중 | 정상 동작. 왼쪽 아래 **종료**로 앱 종료 |
| 설치·실행이 회사 정책으로 차단됨 | 사내 IT 담당자에게 배포 파일과 오류 안내 전달 |

바로가기가 없으면 탐색기에서 아래 파일을 실행할 수 있습니다.

```text
%LOCALAPPDATA%\AVReportHub\bin\AVReportHub.exe
```

문제가 반복되면 실행 중인 버전, 문제가 발생한 화면과 오류 문구를 배포 담당자에게 알려 주세요. 앱 데이터 폴더의 `app.log`에는 연결·실행 진단 기록이 있습니다. 자료 형식과 운영 절차는 [프로젝트 상세 설명서](PROJECT_GUIDE.md)를 참고하세요.

가이드 기준: **v0.1.9 · 2026-10-19**. 앱에 표시된 버전이 다르면 해당 배포본의 도움말을 먼저 확인하세요.
